# Correcciones del formulario — 1 de noviembre de 2026

## Fallos corregidos

- La matriz de escritorio registraba las respuestas pero no mostraba la selección: el CSS del marcador dependía de una clase que no tenían las celdas. Radios y checkboxes ahora representan directamente el estado nativo `checked`.
- El enlace administrativo desde `/simular` apuntaba al frontend estático y devolvía 404. Ahora se construye con la URL del backend ya configurada.
- Un fallo transitorio del sondeo de acceso desmontaba la simulación y descartaba respuestas y CSV en memoria. Ahora conserva la sesión visible con aviso y reintento; una revocación explícita sigue descartándola. Las operaciones continúan siendo autorizadas por el backend.

## Verificación

Se reprodujo el fallo original sobre el bundle compilado: `checked=true` con opacidad cero en el marcador. Con la corrección pasaron 110 pruebas unitarias, TypeScript, ESLint y dos recorridos de navegador sobre el bundle compilado.

Los recorridos comprueban los estilos visibles, además del estado del control: consentimiento, radios, las 18 áreas, selección con teclado, cambio de opción, escritorio/móvil, volver y avanzar, checkboxes, límite de tres y opciones excluyentes. La prueba de simulación verifica que no se invoquen APIs de respuestas reales. Las APIs de esta suite visual están simuladas localmente.

La nueva regresión se ejecuta en el CI del repositorio frontend después del build. Para reproducirla: `npm ci`, `npx playwright install chromium`, `npm run build` y `npm run test:browser`.

Estas comprobaciones son locales y de CI; publicar el commit en GitHub no confirma por sí solo que Coolify haya desplegado la nueva imagen. Las respuestas ya existentes y las configuraciones privadas no forman parte del cambio.
